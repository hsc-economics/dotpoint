# Dotpoint

Current, sourced evidence for HSC Economics, mapped to the dot points of the
Economics 11–12 Syllabus (2025). First draft: Economics only. Legal Studies and
Business Studies come after Economics is right.

## What's in it

| Feature | Where | Notes |
|---|---|---|
| Today | `#today` | One "do this now" action, your dot point map, latest numbers, newest evidence |
| Skills | `#skills` | Skill tree: 7 branches, 39 dot points, mastery levels Familiar → Proficient → Mastered; list view too |
| Examples | `#evidence` | Dated, sourced real-world examples, each with a verified quote; linked to the statistics |
| Stats | `#stats` | 20 indicators from RBA/ABS tables (10 headline figures shown on Home), charts, tables, ready-to-cite sentences, cash rate history |
| Drills | `#drills` | Spaced-repetition flashcards built from evidence, key terms and the latest statistics |
| Essays | `#essay` | Claude marks a practice essay out of 20 on five criteria, checks its statistics against `data/stats.js` and suggests Dotpoint examples. Runs on the viewer's own Claude account, so it only works on the published page |

## Folder layout

```
index.html            page and styles
js/logic.js           pure logic (scheduling, freshness, search, formatting), unit tested
js/app.js             the interface
data/syllabus.js      focus areas, dot point summaries, key terms, skill tree branches
data/evidence.js      evidence cards (each one checked against its source)
data/stats.js         GENERATED by tools/update_stats.py, do not edit by hand
data/questions.js     30 practice essay questions, each linked to dot points
tools/update_stats.py refreshes statistics from the RBA and ABS
tools/build_preview.py makes a local preview copy
tests/                test suite
```

## Everyday jobs

Refresh the statistics (run after each RBA decision, CPI, labour force or GDP release):

```bash
python3 tools/update_stats.py
```

If a download fails, the script leaves the existing data untouched and says why.

Run the tests (uses macOS's built-in JavaScriptCore, or Node.js if installed):

```bash
sh tests/run_tests.sh
```

Preview locally:

```bash
python3 tools/build_preview.py && python3 -m http.server 8765 --directory preview
```

## Running Dotpoint on GitHub (without Claude)

Make this folder the root of a GitHub repository, then once:

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Actions → General → Workflow permissions: **Read and write**.
3. Issues → Labels: create **submission** and **approved**.
4. Put your repository name in `data/config.js` (for example `"jsmith/dotpoint"`) and push.
5. Actions → **Refresh statistics and publish** → Run workflow, to publish the first time.

After that, `.github/workflows/refresh-and-publish.yml` downloads new RBA and ABS figures every
weekday evening, runs the tests, saves any changes and republishes. Turn off the Claude scheduled
task so the two don't overlap.

Suggestions: people use the "Suggest an example or statistic" form (links appear once step 4 is done).
Read the issue, fix anything you need to, then add the **approved** label. `add-submission.yml` turns
it into a card, tests it, publishes it and closes the issue, or comments with what to fix.

Off Claude, essay marking and account sync don't work (they need Claude); progress is saved in the browser.

## Rules for evidence cards

1. Every fact must appear on the linked source page. Prefer primary sources (RBA, ABS, ACCC, ATO, Fair Work, budget.gov.au).
2. Write summaries in your own words. Add ONE short `quote` (under about 20 words) copied exactly from the source, with who said it.
3. `date` is when the event happened; it drives the Fresh / Ageing / Old label.
4. Update `checked` whenever you re-verify a card. Mark fast-moving stories `status: "developing"`.
5. Run the tests: they catch broken dot point links, bad dates and missing fields.
