# Dotpoint

Current, sourced evidence for HSC Economics, mapped to the dot points of the
Economics 11–12 Syllabus (2025). First draft: Economics only. Legal Studies and
Business Studies come after Economics is right.

## What's in it

| Feature | Where | Notes |
|---|---|---|
| Today | `#today` | One "do this now" action, your dot point map, latest numbers, newest evidence |
| Skills | `#skills` | Skill tree: 7 branches, 39 dot points, mastery levels Familiar → Proficient → Mastered; list view too |
| Examples | `#evidence` | Dated, sourced real-world examples, each with a verified quote; linked to the statistics. Also lists news reports collected automatically into `data/news-archive.js` |
| Stats | `#stats` | 20 indicators from RBA/ABS tables (10 headline figures shown on Home), charts, tables, ready-to-cite sentences, cash rate history |
| Papers | `#resources` | Every official HSC Economics past paper (with marking guidelines and marker feedback), NESA band samples, the new-syllabus sample exam and RBA study guides. `tools/update_resources.py` checks NESA and the RBA for new ones every day. Links open the publisher's own copy; no files are stored here |
| Drills | `#drills` | Spaced-repetition flashcards built from evidence, key terms and the latest statistics |
| Essays | `#essay` | Essay checker, no AI: checks each figure against the RBA and ABS history in `data/stats.js`, what the question's verb asks for, structure and key terms, and suggests statistics and examples to add. Runs in the browser; never gives a mark |

## Folder layout

```
index.html            page and styles

js/app.js             the interface
data/syllabus.js      focus areas, dot point summaries, key terms, skill tree branches
data/evidence.js      evidence cards (each one checked against its source)
data/stats.js         GENERATED by tools/update_stats.py, do not edit by hand
data/questions.js     30 practice essay questions, each linked to dot points
data/resources.js     GENERATED by tools/update_resources.py: past papers and study resources

tools/update_resources.py finds new past papers and resources (NESA, RBA Education)
tools/build_preview.py makes a local preview copy
tools/build_icons.py  draws the crayon-style tab icons in icons/
tests/                test suite
```

## Everyday jobs

Refresh the statistics (run after each RBA decision, CPI, labour force or GDP release):

```bash
python3 tools/update_stats.py
```

If a download fails, the script leaves the existing data untouched and says why.

Look for new past papers and resources (GitHub Actions does this every morning at 6am Sydney time):

```bash
python3 tools/update_resources.py
```

It reads the NSW Government sitemap for NESA's Economics exam pack and standards pages, NESA's new-syllabus
assessment pages, and the RBA Education resource pages. It only reads the HTML pages that list documents and
links to the files on the publisher's site (NESA's robots.txt asks crawlers not to fetch its PDFs). If a source
fails, its items from the last good run are kept. To add a source, write a function that returns items and add
it to `SOURCES`.

Run the tests (uses macOS's built-in JavaScriptCore, or Node.js if installed):

```bash
sh tests/run_tests.sh
```

Preview locally:

```bash
python3 tools/build_preview.py && python3 -m http.server 8765 --directory preview
```

## Running Dotpoint on GitHub (without Claude)

Make this folder the root of a GitHub repository, then once:

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Actions → General → Workflow permissions: **Read and write**.
3. Issues → Labels: create **submission** and **approved**.
4. Put your repository name in `data/config.js` (for example `"jsmith/dotpoint"`) and push.
5. Actions → **Refresh statistics and publish** → Run workflow, to publish the first time.

After that, `.github/workflows/refresh-and-publish.yml` downloads new RBA and ABS figures every
weekday evening, runs the tests, saves any changes and republishes. Turn off the Claude scheduled
task so the two don't overlap.

Suggestions and problem reports: people use `suggest.html` and `report.html` (and the "Report a problem"
box on each example and statistic). These are emailed to you by `tools/email-relay.gs`, a small Google Apps
Script that runs in your own Google account and sends from your Gmail to your Gmail as a tidy, readable email.
Set it up once by following the steps at the top of that file, then put its Web app URL (ending in `/exec`)
in `contactEndpoint` in `data/config.js`. Until then, or if sending fails, the forms open the visitor's email
app with the message written out, addressed to `contactEmail`. The relay sends at most 40 emails an hour.

The older GitHub route still works for anyone who opens an issue directly: add the **approved** label
and `add-submission.yml` turns it into a card, tests it, publishes it and closes the issue.

Everything works off Claude. Only account sync needs it; elsewhere progress is saved in the browser.

Search: `google379b03ff488f9ee8.html` proves to Google Search Console that this site is yours. Don't delete it, or the
site drops out of Search Console. `tools/build_preview.py` also writes `sitemap.xml` and the plain pages
`dot-points.html` and `examples.html` for search engines.

## Rules for evidence cards

1. Every fact must appear on the linked source page. Prefer primary sources (RBA, ABS, ACCC, ATO, Fair Work, budget.gov.au).
2. Write summaries in your own words. Add ONE short `quote` (under about 20 words) copied exactly from the source, with who said it.
3. `date` is when the event happened; it drives the Fresh / Ageing / Old label.
4. Update `checked` whenever you re-verify a card. Mark fast-moving stories `status: "developing"`.
5. Run the tests: they catch broken dot point links, bad dates and missing fields.
